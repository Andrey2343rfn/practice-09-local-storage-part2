## Опис роботи

«Особистий щоденник» — вебдодаток на Flutter для ведення записів, відстеження настрою та пошуку за текстом і тегами. SQLite виконує запити через WebAssembly у Chrome. База зберігається в IndexedDB для адреси додатка, тому записи залишаються після оновлення сторінки.

## Запуск у VS Code

Потрібні Flutter SDK із Dart 3.5 або новішої версії та Google Chrome. Відкрий у VS Code папку `journal_9_2`, де лежить `pubspec.yaml`. Виконай у терміналі:

```bash
flutter pub get
if [ ! -f web/sqlite3.wasm ]; then
  curl -fL https://github.com/simolus3/sqlite3.dart/releases/download/sqlite3-2.4.6/sqlite3.wasm -o web/sqlite3.wasm
fi
flutter run -d web-server --web-hostname localhost --web-port=8092
```

Відкрий [localhost:8092](http://localhost:8092) у Chrome. Використовуй ту саму адресу та профіль браузера, щоб відкрити ту саму базу. Для першої перевірки створи тег «Навчання», додай запис із цим тегом і натисни Cmd + R. Запис і тег мають залишитися.

| Файл | Призначення |

## Схема бази даних

Під час першого відкриття `journal_9_2.db` метод `_onCreate` створює таблиці та індекси.

| Таблиця | Поля | Призначення |
| --- | --- | --- |
| `journal_entries` | `id`, `title`, `content`, `mood`, `created_at`, `updated_at`, `is_favorite`, `word_count` | Текст, настрій і дані про кожний запис. |
| `tags` | `id`, `name`, `name_key`, `color`, `created_at` | Назва, колір і дата додавання тегу. Унікальне поле `name_key` запобігає дублюванню назв із різним регістром. |
| `entry_tags` | `entry_id`, `tag_id` | Зв’язок багато до багатьох між записами й тегами. Пара ідентифікаторів утворює складений первинний ключ. |

Зовнішні ключі `entry_tags` мають правило `ON DELETE CASCADE`. Коли користувач видаляє запис або тег, SQLite видаляє відповідні зв’язки. Індекси створюються для дати запису, настрою, назви тегу та `entry_tags.tag_id`.

## Запити й алгоритми

Під час пошуку `LIKE` перевіряє назву та текст. `LEFT JOIN` повертає записи разом із їхніми тегами, зокрема записи без тегів. `EXISTS` перевіряє вибраний тег окремо, тому в результаті залишаються видимими всі теги знайденого запису.

```sql
SELECT j.*, t.id AS tag_id, t.name AS tag_name, t.color AS tag_color
FROM journal_entries AS j
LEFT JOIN entry_tags AS et ON et.entry_id = j.id
LEFT JOIN tags AS t ON t.id = et.tag_id
WHERE (j.title LIKE ? ESCAPE '!' OR j.content LIKE ? ESCAPE '!')
  AND j.mood = ?
  AND EXISTS (
    SELECT 1
    FROM entry_tags AS f
    WHERE f.entry_id = j.id AND f.tag_id = ?
  )
ORDER BY j.created_at DESC, j.id DESC, t.name;
```

Значення для пошуку й фільтрів передаються окремими параметрами. Для статистики SQL групує записи через `GROUP BY` і рахує їх через `COUNT`. Серія днів рахується за унікальними датами поспіль від сьогодні або від учора, якщо за сьогодні запису ще немає.

Метод `saveEntry` змінює запис і його зв’язки з тегами в одній транзакції. Якщо окрема операція завершується помилкою, SQLite скасовує всі зміни цієї транзакції.

## Труднощі та рішення

Під час першого запуску Chrome показав помилку `SqfliteFfiWebException()`. Для запуску SQLite без вебворкера у `journal_db.dart` використано `databaseFactoryFfiWebNoWebWorker`. Перевірка в терміналі також показала, що файл `web/sqlite3.wasm` був відсутній. Після завантаження файлу для версії `sqlite3 2.4.6` та повторного запуску додаток відкрився.
